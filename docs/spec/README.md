# RP Frontend — Spec (working title)

A roleplaying app with an AI Dungeon Master. It's a story generator first, but it has a real game underneath: stats, dice, skills, leveling and death. It runs on local models (LM Studio, Ollama) or cloud models (Anthropic, plus anything OpenAI-compatible). It's built for a non-developer, so it should look and feel like a game, not a developer tool.

## Who it's for

- **Primary user:** an artist, not a developer. Every common action needs a big, obvious, iconned button. Technical settings live behind "Advanced".
- **Builder/tester:** a non-developer working with Claude Code. The code has to stay modular and easy to change in small pieces.

## Core principles

1. **Code keeps the books, the AI tells the story.** The rules engine owns every number (stats, HP, dice, XP, inventory). The AI proposes changes in a structured format; the engine checks and applies them, then hands the result back to the AI to narrate. The AI never does the math.
2. **Memory lives in data, not in the context window.** Names, places, relationships and the order of events are stored in structured records, and only the slice relevant to the current scene goes into the prompt. This is how small or low-context models stay coherent over a long campaign.
3. **Every state change belongs to a message.** If you regenerate, edit or rewind a message, its effects on the game state are undone with it.
4. **No favoritism.** Rolls are real and consequences are real. The character can die. The player can still override anything on purpose (free rerolls, manual edits), because it's their story.
5. **Simple by default.** One model picker and one "Play" button. Everything else is optional.
6. **Modular.** Each feature is its own module with a clear interface (see [01-architecture.md](01-architecture.md)), so any one part can be swapped or extended without touching the rest.

## Glossary

- **Card:** a portable character file (portrait, description, personality). Compatible with SillyTavern/Chub Character Card V2/V3.
- **Sheet:** the game stats for one character in one campaign. It links to a card.
- **Campaign:** one adventure. It holds its world, lorebooks, sheets, event log and saves.
- **Event:** one recorded change to game state (damage, an item gained, a skill XP gain…). Each event belongs to a message.
- **Turn:** one player input and the DM response(s) to it.
- **Job:** a task the AI does (narrate, referee, scribe, suggest…). Each job can use a different model in Advanced settings.
- **Swipe:** an alternate version of the same AI response (generated by regenerating).
